# 功能规划

> 依据：对同类开源项目的调研（2026-09）。调研对象与结论见文末「调研依据」。

## 当前能力盘点

| 环节 | 已实现 |
| --- | --- |
| 抓取 | 单篇/多篇批量抓正文与图片、按分组归档、重复链接复用 |
| 风格量化 | 版式（字号/字色/行距/对齐）、段落（平均段长/最长段/分布）、节奏（几段一图）、装饰（加粗/引用/分割线/表情密度）、语气描述 |
| 风格档案 | 多号独立档案、按来源自动拆分、导入导出 |
| 生成 | 参数约束 + 词汇/句式黑名单 + 节奏要求 + 事实边界；去 AI 味二次改写（三重校验，失败回退） |
| 篇幅 | 真实口径计数、目标取区间中值、不足自动续写补齐 |
| 配图 | 分组取图、槽位点选、换图、一键重配 |
| 导出 | 内联样式富文本、空段落承载间距、图片原链还原 |
| 辅助 | 选题助手（AI 出选题 / 提示词外带解析） |

顺带修掉的两个缺陷（同一批改动留下的半成品）：

- `argumentBrief` / `anchorBrief` 只加了调用、没有实现，导致 `buildGenPrompt()` 抛 `ReferenceError`，**文章生成功能整体不可用**；

## 建议新增（按优先级）

### P0 — 直接提升"像不像"的程度

**1. 风格量化补齐三层：选题逻辑 / 素材策略 / 认知框架**

现在的量化只覆盖了「表层语言 + 文章结构 + 视觉风格」三层。参考 writing-dna-skill（1.2K star）的六层框架，缺的三层恰恰决定"为什么像"而不只是"看起来像"：

| 层 | 内容 | 现在 | 建议补的字段 |
| --- | --- | --- | --- |
| 表层语言 | 词频、句长、标点习惯 | 部分有 | 已有段长/节奏，可加标点习惯（如「。。。」代替省略号） |
| 文章结构 | 怎么开头、怎么展开、怎么收尾 | 部分有 | 已有段落节奏，可加开头/收尾方式标签 |
| **选题逻辑** | 常写什么话题、从什么角度切入 | **缺** | 话题类型分布、切入角度（亲历/评测/吐槽/对比） |
| **素材策略** | 引用哪类来源、数据怎么用 | **缺** | 论据偏好（数据/案例/他人引述/个人体验）及其占比 |
| **认知框架** | 反复出现的立场与价值判断 | **缺** | 高频观点、偏爱与抵触的表达 |
| 视觉风格 | 配图方式与排版习惯 | 有 | 已有图片形态与表情密度 |

落地方式：分析阶段在现有统计之外，增加一轮「论点抽取」（从非空段落中抽取观点句与论据句并分类），结果写入档案。生成时把这三层一并注入提示词，让选题角度和论证方式也贴近目标号。

**2. 范例段落检索注入（few-shot 锚点）**

现状：生成时只给「参数 + 一段语气描述」，模型靠描述去还原风格。
问题：描述天然有损，风格细节（怎么吐槽、怎么抛数据）传不过去。

建议：分析时把样例文章切成段落并打标签（开场 / 转折 / 收尾 / 吐槽 / 数据说明 / 过渡），存进档案；生成时按段落用途检索 3-5 个范例片段作为 few-shot 锚点注入提示词。

依据：开源项目 style-retrieval 做了对照实验（以罗素的散文为样本，4 个模型，盲评排名），结果很明确：

| 方法 | 平均排名 | 获第一比例 | 进前二比例 |
| --- | --- | --- | --- |
| Agent Statistical（从策展目录检索范例） | 1.74 | 48% | 85% |
| Few-shot（少量范例直接给） | 1.94 | 33% | 78% |
| Author Author（只给作者名） | 2.65 | 18% | 31% |
| Generic（通用提示） | 3.67 | 1% | 6% |

结论：**检索范例优于纯参数描述，纯描述优于只报风格名**。本项目目前的形态介于「Author」和「Generic」之间，加检索范例是最直接的提升手段。

---

### P1 — 体验缺口

**3. 生成历史版本**

现状：生成结果只保留最近一次（浏览器本地存储单份），重新生成会覆盖。
建议：每次生成存一版，提供版本列表、并排对比、一键回滚。
依据：TypeDuck 每文档保留 30 版快照；写作场景里「上一版其实更好」非常常见。

**4. 多格式导出**

现状：复制富文本 + 导出 HTML。
建议：加 Markdown / Word(.docx) / PDF 导出。
依据：TypeDuck 提供四种格式；需要投稿、存档、给他人审阅时，HTML 不够用。

**5. 图池治理（去重与质量筛选）**

现状：抓取的图片全部入池，重复图、低质图、水印图一概保留。
建议：按感知哈希（pHash）去重、过滤过小尺寸图、可选按图注文本聚类。
依据：当前 articles/ 已 355 MB / 1170 个文件，池子越大，自动配图的命中质量越容易被稀释。

---

### P2 — 差异化加分

**6. 深色模式预览**

公众号在深色模式下会自动反色，明暗配色不当时会崩（浅底深字反色后对比度过低）。
建议：预览面板加一个深色模式开关，按微信的转换算法渲染。
依据：WeMD 把这作为主打卖点（基于微信官方开源的 mp-darkmode 算法迁移，还原度称 98%+）。

**7. 外链自动转脚注**

公众号正文不支持外链，粘贴后链接会失效。
建议：导出时把所有外链搬到文末「参考资料」，正文位置留 [n] 角标，网址以纯文本保留。
依据：md-wechat 已有该功能，痛点明确。

---

### P3 — 稳健性

**8. 抓取失败兜底**

现状：单篇抓取失败只提示；原文章被删则无法再取。
建议：失败自动重试一次 + 落盘原文 HTML 快照（已抓过的可离线复用）。
依据：本项目的参考研究样本就是这么存下来的（`research/wx_article.html`），文章被删后仍能复用。

**9. 单篇风格档案的分享**

现状：支持全部档案批量导出/导入。
建议：增加单档案导出，便于在多个设备或多人之间传递风格资产。

## 不建议做的

- **用微调模型做风格迁移**（如 StyleLLM 路线）：效果上限高，但要训练和部署，与「双击即用、零依赖」的定位冲突。用提示词 + 检索范例足够。
- **接入图床**：多数同类工具走图床外链，但公众号会转存图片，本地素材库更符合"自己的图自己管"的用法。

## 一句话结论

同类开源项目集中在「**已有内容 → 排版**」这一段，本项目走的是「**学到风格 → 生成内容 → 再排版**」，方向不同、不构成重复。

最值得补的两件事：**把风格量化从三层扩到六层**、**把参数描述升级为参数 + 检索范例**——这两项都直接决定"写出来像不像"，其余都是体验层面的完善。
