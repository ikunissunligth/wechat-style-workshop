# 公众号风格工坊

> 让 AI 写出来的公众号文章像某个号本人写的，而不是像 AI 写的。

从一篇真实文章出发，量化它的版式与文风，固化成可复用的**风格档案**，再按档案生成新稿、自动配图、一键复制到公众号后台。全流程在本机完成，密钥与素材不出电脑。

## 它解决什么问题

直接用大模型写公众号，反复出现三类问题：

1. **风格不可描述**——"口语化一点"对模型不构成约束，写出来仍是结构工整、连接词密集的机器文风。
2. **篇幅不可控**——要两千字往往只给一千五，只能自己数。
3. **配图排版无法自动化**——找图、调尺寸、插位置，一篇稿子能磨掉一小时。

## 核心能力

| 环节 | 能力 |
| --- | --- |
| 抓取 | 贴文章链接，自动抓正文与全部图片并按分组归档；支持一次贴多篇批量抓图，单篇失败不中断 |
| 风格量化 | 把版式与文风转成参数：字号 / 字色 / 行距 / 对齐、平均段长 / 最长段 / 段长分布、图文间隔、装饰元素与行内表情密度，另由模型提炼一段语气描述 |
| 论证画像 | 统计样例文章的论据类型占比（数字 / 引述 / 亲身经历 / 反问 / 口语词），生成时按同样比例组织论据——只量化语言表层不足以"像"，还得让支撑观点的方式一致 |
| 选题与立场画像 | 按关键词词典统计话题分布（评测 / 数码 / 吐槽 / 教程 / 生活 / 热点）与切入角度（亲历叙事 / 对比评测 / 吐槽开炮 / 提问互动 / 科普讲解），并抽取反复出现的价值判断句，生成时一并注入——对应风格六层框架里的「选题逻辑」与「认知框架」层 |
| 语气锚点 | 从样例文章里按用途挑出真实段落（开篇 / 数据型论据 / 口语互动 / 短句成段 / 展开段 / 收尾）作为 few-shot 锚点注入提示词，只作语气与节奏参照、明确禁止照抄内容 |
| 风格档案 | 一个号一份独立档案，可长期复用；批量分析多个号时按来源自动拆分，避免参数被平均成"四不像"；支持单档案导出（跨设备 / 多人传递）与批量导入导出 |
| 文章生成 | 以档案参数为约束，叠加词汇与句式黑名单、句长节奏要求、事实边界限定；生成后做一次"去 AI 味"二次改写（先扫描十类 AI 味模式族生成定向清单，再按清单做减法：删过渡词、拆对仗句式、打散均匀句长），改写结果需通过标记数量 / 字数 / 标题 / **AI 味残留是否下降**四重校验，不合格自动回退原稿 |
| 生成历史 | 每次生成自动存一版快照（上限 20 版），支持版本列表与一键回滚；回滚前当前稿自动存档，不会丢 |
| 篇幅保障 | 确定性汉字计数（排除标题与配图标记），低于目标区间自动续写补齐；目标取区间中值而非下限，避免贴着红线交差；工具栏实时显示字数与预计阅读时间 |
| 配图 | 按档案绑定的分组从本地素材池取图，槽位点击即换（自有素材优先，网络搜图作兜底），支持一键重配 |
| 图池治理 | 扫描全部已抓图片：同字节重复图（MD5 指纹）分组展示、过小配图（宽或高 <200px）标出，勾选确认后从磁盘清理并同步索引；行内表情不受小图规则影响 |
| 导出 | 输出带内联样式的富文本，粘贴到公众号后台不跑版：段间距由空段落承载（微信后台不认垂直外边距），图片还原为原始链接；支持导出 Markdown 源稿 |
| 外链转脚注 | 公众号只保留 mp.weixin.qq.com 的可点击链接，其余外链粘贴时会被剥掉、网址一并丢失。导出时自动把外链转成「文字 + [n] 角标」，网址收进文末【参考资料】以纯文本保留 |
| 排版微调 | 在档案基础上临时覆盖字号 / 主色 / 行距（会话级，不改档案本身），预览与导出同步生效 |
| 抓取稳健性 | 单篇抓取失败自动重试一次；每次抓取成功后落盘原文 HTML 快照，文章被删后仍能离线复用（结果中会标注来自快照） |
| 选题助手 | 按账号定位与当次素材产出候选选题，确认后直接填入生成表单；也可把提示词复制给其他模型使用 |
| 排版规范化 | 中文与英文之间自动补空格、中文语境里的半角标点转全角、省略号与重复标点收敛；可一键应用到正文，也能在复制 / 导出时自动生效（数字与中文之间不加空格，避免把「9月16日」「第3章」拆散） |
| 发布前体检 | 本地规则扫描后给出评分与逐项清单：广告法绝对化用语、诱导分享、金融与医疗违规表述、站外导流、AI 味残留、常见错别字、标题长度、正文字数、配图与未填充槽位、外链；命中词点击可在编辑器里定位，可自动修的一键修 |
| 标题与摘要 | 按档案文风一次生成多个候选标题并打分（带字数提示，超过 20 字会标出手机端折行风险），附 3 条 54 字内摘要；点一下即替换正文标题 |
| 深色模式预览 | 按微信深色模式的反色规则渲染预览（背景压暗、正文转浅灰、图片略降亮），用来检查配色在夜间会不会糊 |
| 多格式导出 | 富文本复制、HTML、Markdown 源稿、Word（.doc，Word / WPS 可直接打开）、PDF（调用浏览器打印另存） |

## 与同类项目的差异

同类开源项目（[md-wechat](https://github.com/laogou717/md-wechat)、[WeMD](https://github.com/litong-2017/WeMD)、[wechat-markdown-editor](https://github.com/jwangkun/wechat-markdown-editor)、[TypeDuck](https://github.com/efarsoft/TypeDuck) 等）集中在 **Markdown → 排版**这一段：把已经写好的内容转成公众号能贴的样式，通常配主题库与代码高亮。

本项目的切入点不同：**先解决"怎么写"，再解决"怎么排"。** 内容不是人工写好的，而是从一篇真实文章学到风格后生成出来的。

| 能力 | Markdown 排版类工具 | 本项目 |
| --- | --- | --- |
| 风格量化（从真实文章学参数） | ✗ | ✓ |
| 六层风格画像（语言/结构/选题/素材/认知/视觉） | ✗ | ✓ |
| 按档案生成正文 | ✗ | ✓ |
| 篇幅硬校验与自动补齐 | ✗ | ✓ |
| 生成历史版本与回滚 | ✗（部分有快照） | ✓ |
| 本地素材库 + 自动配图 + 图池去重治理 | ✗（多为图床外链） | ✓ |
| 主题/排版微调 | ✓（内置主题 + 自定义 CSS） | ✓（档案参数 + 会话级微调） |
| 中英文排版规范化 | 部分支持 | ✓（一键 + 导出自动生效） |
| 深色模式预览 | WeMD 支持 | ✓ |
| 发布前合规体检（极限词 / 诱导 / 导流 / 违规承诺） | ✗ | ✓（本地规则，正文不出机） |
| AI 标题候选与打分 | 部分支持 | ✓（按风格档案生成） |
| 导出 Markdown 源稿 | ✓ | ✓ |
| 导出 Word / PDF | 部分支持 | ✓ |
| 排版导出到公众号 | ✓ | ✓ |
| 本地化部署、数据不出机 | 部分支持 | ✓ |

## 快速开始

**环境**：Windows + Python 3.8+（仅依赖标准库），推荐 Chrome / Edge。

```bash
# 1. 启动本地服务
双击 start.bat
#    或在命令行执行： python serve.py

# 2. 浏览器打开
http://127.0.0.1:8765
```

**配置模型接口**：进入「设置」页填写 API 地址（baseUrl 填到 `/v1` 一级）、API Key、模型名，点「保存」后「测试连接」。接口兼容任意 OpenAI 格式服务（阿里云百炼、火山方舟、DeepSeek 等均可）。密钥仅保存在浏览器本地存储。

**使用流程**：

1. 风格分析 → 贴参考文章链接 → 点「链接分析」；图不够可在「补充图源文章」里再贴几篇
2. 填档案名称 → 保存为风格档案
3. 文章生成 → 选档案、填主题与要点（可用「选题助手」）、选篇幅 → 生成文章
4. 自动配图 → 点击槽位可换图
5. 发布前点「发布前体检」看评分与问题清单 → 需要的话用「排版规范化」「标题 / 摘要」修一修
6. 「复制到公众号」→ 后台粘贴（或导出 Word / PDF 存档）

## 技术栈与目录结构

无框架：单文件前端 + Python 标准库本地服务 + SQLite（同样是标准库 `sqlite3`，无需安装数据库）。

```
公众号风格工坊/
├── index.html          前端单页应用（界面 + 全部业务逻辑）
├── serve.py            本地服务：静态托管、文章抓取（重试+快照）、图片落盘、图池扫描清理、模型请求转发、图片反向代理、业务 API
├── db.py               数据层：11 张表的建表与 CRUD、六层拆表、实验表、首次启动的历史迁移
├── data/workshop.db    SQLite 库（首次启动自动创建，已从 articles/ 导入历史数据；不进版本库）
├── start.bat           一键启动
├── check.js            静态检查：脚本语法与 ID 引用一致性
├── test_app.js         前端功能测试（无头文档环境，174 项断言）
├── test_db.py          数据层测试（建表/迁移/CRUD/六层/实验表，50 项断言）
├── test_full.js        端到端测试（需服务运行，38 项用例）
├── test_wordcount.js   字数统计口径与自动续写测试
├── test_multifetch.js  多链接批量抓图测试
└── research/           参考文章排版量化分析
```

### 数据是怎么存的

**SQLite 是真源，浏览器本地存储是缓存。** 启动时以库为准覆盖本地，本地每次保存后异步回写，接口不可用就静默降级为纯本地模式（断网也能写）。

| 数据 | 落库 | 留在浏览器 |
| --- | --- | --- |
| 公众号账号、抓取文章、原文快照 | ✓ | |
| 风格档案、六层画像（`profile_layer`） | ✓ | 缓存 |
| 图片分组与素材索引（文件仍在 `articles/`，库里存路径与元信息） | ✓ | |
| 生成记录、生成指标、盲评记录 | ✓ | 生成历史另存一份（离线可回滚） |
| **API Key**、排版微调、界面主题 | ✗ | ✓ —— 密钥不出机，这是承诺 |

11 张表：账号 / 文章 / 原文快照 / 风格档案 / 六层画像 / 图片分组 / 图片素材 / 生成记录 / 生成指标 / 盲评记录 / 抓取日志。其中 `profile_layer` 与 `generation_metric` 是把"六层画像"和"效果评估"变成可 SQL 查询的数据，论文里的统计表和图直接从这两张表出。

接口 25 个（`/api/stats` 起，覆盖账号、档案、分析、生成、指标、评估、素材、日志的增删改查）。

关键技术处理：

- **长请求稳定性**：模型请求优先流式接收，网关不支持时自动回退普通请求；上游请求绕过系统代理直连，避免长连接被代理中断。
- **排版一致性**：段间距与图片样式规则由一篇真实公众号文章的结构统计反向校准（图片上方不插空段落、下方插一个空段落，与基准文章的 0/46 与 43/46 一致）。
- **改写安全阀**：去 AI 味改写后校验标记数量、字数、标题与 AI 味残留是否下降，任一不符即回退原稿，保证改写环节只会变好不会改坏。
- **AI 味检测**：`detectAiFlavor()` 按十类中文 AI 味模式族扫描（宏大开场、元话语套话、对仗句式、工整排比、硬拆三点、商业黑话、冗余介词、段段连接词、被字句公文腔、空泛高评价），外加句长变异系数衡量的"句长均匀"；每一类都给出**怎么改**与**什么时候别改**的双向判据，命中数 ≥3 才算提醒、偶发不计。检测结果以 `aiFlavor` / `aiFlavorPer1k` / `sentLenCv` 三个指标入库，可直接用于效果对比。

## 已知限制

- 事实准确性依赖提示词中的边界约束，可降低编造概率但无法根除，涉及价格、参数与引用的内容仍需人工核对。
- 生成一篇长文最多需要三次模型调用（首写 + 去 AI 味改写 + 字数补齐），耗时约两到三分钟。
- 单机部署，无多人协作与云端同步（数据库是本机 SQLite，换机器靠档案的导入导出）。
- 微信公众号不提供免登录的历史文章列表接口，文章链接需从公众号历史消息中复制。
